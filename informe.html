1. Introducción y objetivos

Stark Industries necesita supervisar un reactor experimental mediante telemetría IoT para observar la carga del núcleo, la estabilidad del campo, la refrigeración, la latencia de JARVIS y el consumo de los repulsores. ThingSpeak proporciona el canal de almacenamiento, visualización y acceso HTTP que permite centralizar estas mediciones.

El objetivo es definir el canal de cinco campos e implementar una aplicación ejecutable que permita leer y escribir sus mediciones. La aplicación procesa las diez muestras experimentales del enunciado y comunica los resultados o errores de conexión en la terminal.

3. Aplicación desarrollada

Se implementó una aplicación de consola en Python 3, sin dependencias externas. El módulo main.py separa la configuración del canal, las llamadas HTTP y la presentación de resultados. La configuración se lee desde variables de entorno definidas en .env.

La aplicación ofrece cinco operaciones:

  • preview: muestra las diez muestras sin conexión ni credenciales.
  • write: envía una medición de cinco valores y muestra el identificador de entrada.
  • read: recupera y presenta las últimas mediciones del canal.
  • samples: carga todas las muestras del enunciado, respetando al menos 15 segundos entre escrituras para evitar rechazos por frecuencia.
  • web: sirve un panel local con un gráfico histórico por campo, una tabla de lecturas, actualización manual y envío de mediciones; las claves permanecen en el servidor.

Se validan los límites 0–100 de los tres primeros campos, los valores no negativos de latencia y consumo, el número de resultados solicitado y la disponibilidad de las claves necesarias. Los errores HTTP y de conectividad se muestran sin imprimir las claves.

4. Instalación, configuración y uso

  1. Instalar Python 3.10 o posterior y descargar/descomprimir el directorio actividad2_iot.
  2. Crear un canal público con los cinco campos indicados y copiar su ID y claves API.
  3. Copiar .env.example a .env, sustituir localmente los valores por las credenciales del canal. La aplicación carga automáticamente sus variables al ejecutar read, write, samples o web; las variables ya definidas en el entorno tienen prioridad.
  4. Desde el directorio de la aplicación, ejecutar:
python3 main.py --help
python3 main.py preview
python3 main.py write --field1 52.4 --field2 96.8 --field3 35.2 --field4 118.6 --field5 42.3
python3 main.py read --results 10
python3 main.py samples
python3 main.py web

Al ejecutar python3 main.py web, abrir http://127.0.0.1:8000 en el navegador. El panel muestra un gráfico histórico independiente para cada uno de los cinco campos; el selector limita cuántas lecturas se consultan. El botón de actualización vuelve a consultar ThingSpeak; el formulario envía los cinco valores y actualiza la lectura después de una escritura correcta.

La operación samples puede tardar aproximadamente 135 segundos, ya que el envío de las diez filas requiere nueve esperas de 15 segundos. El archivo .env está excluido mediante .gitignore y debe mantenerse fuera del ZIP si contiene claves reales.

6. Verificación y evidencias

La suite automatizada se ejecuta con python3 -m unittest discover -s tests -v. Las pruebas verifican la composición de una escritura con cinco campos, la lectura JSON, el tratamiento de una escritura rechazada, la validación del intervalo mínimo, la configuración ausente y la vista previa sin credenciales. Las peticiones HTTP se simulan; por ello estas pruebas no sustituyen la comprobación en el canal real.

Resultado local: 7 pruebas unitarias superadas. La vista previa muestra las diez filas del enunciado sin realizar llamadas a la API.

Evidencias que debe incorporar el grupo:

  1. Captura de la configuración del canal con sus cinco campos y visibilidad pública.
  2. Captura de API Keys con las claves ocultas y el Channel ID visible.
  3. Capturas de terminal de una lectura y una escritura correctas, evitando mostrar claves.
  4. Captura de la vista del canal que muestre las mediciones después de cargar los datos.

No se adjuntan capturas remotas ficticias: deben generarse después de configurar y ejecutar la aplicación con el canal real del grupo.

7. Conclusiones

La solución integra una aplicación ejecutable con las operaciones HTTP de ThingSpeak y conserva las diez muestras del enunciado en el orden de los campos definido. El uso de variables de entorno evita incluir credenciales en el código y el intervalo entre escrituras reduce errores por limitación de frecuencia. Para cerrar la validación de extremo a extremo es imprescindible crear el canal público del grupo, cargar las claves localmente, ejecutar las operaciones y añadir las evidencias reales requeridas.
